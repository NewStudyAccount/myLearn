23 种经典的模式，根据用途我们又可以分为三大类，分别为创建型模式、结构型模式和行为型模式。

有一些重要的设计原则在开篇和大家分享下，这些原则将贯通全文：

1、面向接口编程，而不是面向实现。这个很重要，也是优雅的、可扩展的代码的第一步，这就不需要多说了吧。
2、职责单一原则。每个类都应该只有一个单一的功能，并且该功能应该由这个类完全封装起来。
3、开闭原则。对修改关闭，对扩展开放。对修改关闭是说，我们辛辛苦苦加班写出来的代码，该实现的功能和该修复的 bug 都完成了，别人可不能说改就改；
对扩展开放就比较好理解了，也就是说在我们写好的代码基础上，很容易实现扩展。


# 创建型模式

创建型模式的作用就是创建对象，说到创建一个对象，最熟悉的就是 new 一个对象，然后 set 相关属性。
但是，在很多场景下，我们需要给客户端提供更加友好的创建对象的方式，尤其是那种我们定义了类，但是需要提供给其他开发者用的时候。

## 简单工厂模式
创建派生自同一个父类的的对象的工厂。
见 类 ``FoodFactory``
注意：强调职责单一原则，只创建各种Food
特点：
工厂类集中了所有产品的创建逻辑
客户端不需要知道具体类的类名，只需要知道参数
当增加新产品时需要修改工厂类（违反开闭原则）


## 工厂模式
简单工厂模式很简单，如果它能满足我们的需要，我觉得就不要折腾了。之所以需要引入工厂模式，是因为我们往往需要使用两个或两个以上的工厂

一个工厂只创建一个产品。当有新的产品时，则增加新的工厂，符合开闭原则。
特点：
每个具体工厂负责创建具体产品
符合开闭原则，新增产品时只需增加新的工厂类
结构更灵活，降低了工厂类的复杂度



## 抽象工厂模式
当涉及到产品簇的时候使用
场景类比
想象你去电脑城买电脑。
普通工厂：只能单独买“联想键盘”、“戴尔鼠标”。
抽象工厂：直接买“联想套装”（键盘 + 鼠标 + 主机）或“戴尔套装”——一套产品族一次性配齐。

```java
// 抽象产品
interface Keyboard {}
interface Mouse {}

// 具体产品
class LenovoKeyboard implements Keyboard {}
class DellKeyboard  implements Keyboard {}
class LenovoMouse   implements Mouse {}
class DellMouse     implements Mouse {}

// 抽象工厂
interface ComputerFactory {
    Keyboard createKeyboard();
    Mouse    createMouse();
}

// 具体工厂
class LenovoFactory implements ComputerFactory {
    public Keyboard createKeyboard() { return new LenovoKeyboard(); }
    public Mouse    createMouse()    { return new LenovoMouse();   }
}

class DellFactory implements ComputerFactory {
    public Keyboard createKeyboard() { return new DellKeyboard(); }
    public Mouse    createMouse()    { return new DellMouse();   }
}

// 客户端
public class Client {
    public static void main(String[] args) {
        ComputerFactory factory = new LenovoFactory();
        Keyboard k = factory.createKeyboard();
        Mouse    m = factory.createMouse();
    }
}
```

使用场景
需要一次性创建一整套相互配套的对象（不同操作系统 UI、不同数据库方言、不同云厂商 SDK）。
希望屏蔽具体类名，方便在未来切换整套系列（例如从联想换到戴尔）。
产品族扩展困难（新增“耳机”就要改动所有工厂），但增加系列容易（再加华硕工厂即可）。

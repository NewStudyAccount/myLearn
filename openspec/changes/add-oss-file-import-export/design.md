## Context

myproject-oss 模块当前使用 S3OssClientFactory 基于 AWS S3 SDK 实现对象存储操作，支持 MinIO 等 S3 兼容存储。现有功能仅支持单文件上传和下载，且存在硬编码配置名、存根方法未实现等问题。本次变更需要在现有架构上扩展批量导入/导出和跨存储迁移能力。

## Goals / Non-Goals

**Goals:**
- 支持将 OSS 文件批量导出到本地（下载）
- 支持将本地文件批量导入到 OSS（上传）
- 支持在不同 OSS 配置之间直接传输文件（跨存储迁移）
- 完善现有存根方法，支持指定配置名操作
- 提供 REST API 和前端管理界面

**Non-Goals:**
- 不涉及文件内容解析或转换（如图片压缩、格式转换）
- 不实现增量同步或定时任务
- 不改变现有 sys_oss_config 和 sys_oss_file 数据库表结构
- 不引入新的存储后端（如阿里云 OSS SDK）

## Decisions

### 1. 使用流式传输实现跨存储迁移
**选择**: 文件从源 OSS 下载为 InputStream，直接上传到目标 OSS，不写入本地磁盘。  
**替代方案**: 先下载到本地临时目录，再上传到目标。  
**理由**: 避免本地磁盘 IO 瓶颈，支持大文件迁移，减少临时文件清理问题。

### 2. 批量操作使用异步任务模式
**选择**: 批量导入/导出通过提交任务返回任务 ID，前端轮询查询进度。  
**替代方案**: 同步阻塞等待所有文件处理完成。  
**理由**: 批量操作耗时较长，同步模式会导致 HTTP 超时。异步模式提供更好的用户体验。

### 3. 复用现有 OssClientFactory 接口
**选择**: 新功能通过 OssClientFactory 接口获取 S3Client 实例，不引入新的客户端管理机制。  
**替代方案**: 为迁移功能创建独立的客户端池。  
**理由**: 现有 Caffeine 缓存机制已足够，避免重复实现。

### 4. 文件列表基于 sys_oss_file 表查询
**选择**: 导出/迁移操作从 sys_oss_file 表读取文件元数据，再根据 file_url 获取实际文件。  
**替代方案**: 直接列举 OSS bucket 中的对象。  
**理由**: 复用现有元数据，支持按条件筛选，与数据库记录保持一致。

### 5. 引入 EasyExcel 处理导入文件清单
**选择**: 用户通过上传 Excel 文件指定要导入的本地文件列表。  
**替代方案**: 使用 CSV 或 JSON 格式。  
**理由**: Excel 在企业环境中更通用，EasyExcel 与项目技术栈兼容且性能良好。

## Risks / Trade-offs

- **[大文件内存占用]** → 流式传输时使用分块读写（AWS SDK TransferManager），避免一次性加载整个文件到内存
- **[批量任务失败处理]** → 部分文件失败时记录失败原因，继续处理剩余文件，最终返回成功/失败统计
- **[并发控制]** → 限制同时进行的迁移任务数量，避免 OOM 或连接池耗尽
- **[网络超时]** → 跨存储迁移依赖网络，设置合理的超时时间和重试策略
